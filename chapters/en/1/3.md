# Your First Repository on the Hub

Ready to contribute to the AI community? Creating your first repository on the Hugging Face Hub is easier than you might think! Whether you want to share a model, dataset, or just experiment with the platform, this section will guide you through the process.

Think of a Hugging Face repository like a GitHub repo, but specifically designed for machine learning. It uses Git under the hood but with specific features for machine learning. Most importantly, it allows you to share your huge files through the power of [Xet](https://huggingface.co/xet-team)!

> [!TIP]
> Don't worry about having a model to share. We're just going to create a simple repository to get you started.

## Creating Repos Through the Web Interface

The web interface is the easiest way to get started. No command-line tools needed!

### Step 1: Create Your First Model Repository

1. Go to [huggingface.co/new](https://huggingface.co/new)

2. Name your repository something descriptive like `my-first-model`

3. Choose a model liscense like MIT or Apache-2.0

4. Choose "Public" visibility to share with the community.

6. Click "Create Model"

### Step 2: Add a Model Card (README.md)

Every good repository needs documentation. The README.md file serves as your model card - a comprehensive description of what your model does. Hugging Face READMEs are a bit special because they can contain more than just text. They can contain metadata that helps the Hub understand your model, like its license, tags, and language. This exposes your model to the community and helps others find it. For example, if your model is for the French language, you might add `language: fr` to the README.md file. This will allow users to filter for French models in the Hub.

1. **Click "Create new file" and name it `README.md`**

2. **Use this template to get started:**

```markdown
---
license: mit
tags:
- text-generation
language:
- fr
---

# My French Model

This is my French model repository on Hugging Face! 🎉
```

> [!TIP]
> The above README.md file will be displayed in the model card when someone views your model. This is a very minimal model card, but you can add more information to it to make it more informative. For example, you can add a description of the model, its capabilities, and its limitations.
>
> If you're publishing a model for real, check out the [Model Card documentation](https://huggingface.co/docs/hub/model-cards) for more information on how to write a good model card.


## Using the Python SDK to create your repository

For more control and automation, we will use the `huggingface_hub` Python library. This is especially useful when working programmatically or with large files.

In some cases, you might want to create your repository programmatically. For example, if you're publishing a dataset as part of an application.

### 1. Create a repository

First, we need to initialize the API client and create a new repository.

```python
from huggingface_hub import HfApi, create_repo
import os

# Initialize the API client
api = HfApi()

# Create a new repository
repo_name = "your-username/my-second-model"

repo_url = create_repo(
    repo_id=repo_name,
    repo_type="model",
    private=False  # Set to True for private repos
)
```

### 2. Create and Upload a Model Card Programmatically

Just like in the web interface, we can create a model card programmatically. This time we will use the `ModelCard` class to create the model card and push it to the repository, and the `ModelCardData` class to define the model metadata.

```python
from huggingface_hub import ModelCard

card_data = ModelCardData(language='fr', license='mit', tags=['text-generation'])
card = ModelCard.from_template(
    card_data,
    model_id='your-username/my-second-model',
    model_description="this model does this and that in French",
    developers="your-username",
    repo="https://github.com/your-username/my-second-model",
)

card.push_to_hub(repo_name)
```

### 3. Upload Files Programmatically

Next, we can upload the files to the repository. We will upload the file.txt file and the model card. We can specify the path in the repository and the local path of the file.

```python
# Upload a single file
api.upload_file(
    path_or_fileobj="my_model_files/file.txt",  # Local file path
    path_in_repo="file.txt",   # Name in repository
    repo_id=repo_name,
    repo_type="model"
)
```

For convenience, we can upload a whole directory at once.

```python
# Upload multiple files from a directory
api.upload_folder(
    folder_path="./my_model_files",
    repo_id=repo_name,
    repo_type="model"
)
```

While we're at it, we can interact with the source control system of the Hub and add a commit message and description. This is useful for tracking changes and for collaboration with others.

```python
# Upload with commit information
api.upload_file(
    path_or_fileobj="model_weights.bin",
    path_in_repo="pytorch_model.bin",
    repo_id=repo_name,
    repo_type="model",
    commit_message="Add trained model weights",
    commit_description="Model trained for 10 epochs on custom dataset"
)
```

## Using the CLI to create your repository

The Hugging Face CLI provides a convenient way to manage repositories directly from your terminal. This is perfect for automation scripts or when you prefer command-line workflows.

### Prerequisites

First, install the Hugging Face Hub library (which includes the CLI):

```bash
# Install the hub library with CLI support
uv pip install huggingface_hub
```

Then authenticate with your Hugging Face account:

```bash
# Login to your account
hf auth login
```

When prompted, enter your User Access Token from [your settings page](https://huggingface.co/settings/tokens).

### 1. Create a repository

First, let's create a repository with the CLI:

```bash
hf repo create Wauplin/my-first-model
```

### 2. Create and Upload a Model Card

Next we need to create a model card. Here, we will use the `cat` command. Just to maximize out CLI vibes! But you can use any text editor you want.

```bash
# Create a README.md file
cat > README.md << 'EOF'
---
license: mit
tags:
- text-generation
language:
- fr
---

# My Third Model

This is my third model repository created using the Hugging Face CLI! 🚀
EOF

# Upload the model card to your repository
hf upload your-username/my-third-model README.md
```

These commands create the README.md file in the local directory and upload it to the repository.

### 3. Upload Files Using the CLI

The CLI makes it easy to upload individual files or entire directories.

```bash
# Upload a single file
hf upload your-username/my-third-model ./local_file.txt

# Upload a file to a specific path in the repo
hf upload your-username/my-third-model ./local_file.txt file.txt

# Upload an entire directory
hf upload your-username/my-third-model ./my_model_files/

# Upload files matching a pattern
hf upload your-username/my-third-model "./model_files/*.bin"
```

Just like with the Python SDK, you can also add commit messages:

```bash
# Upload with commit information
hf upload your-username/my-third-model \
  ./model_weights.bin \
  --commit-message "Add trained model weights"
```

### 4. Download Files from the Hub

The CLI also makes downloading files simple:

```bash
# Download a specific file
hf download your-username/my-third-model pytorch_model.bin

# Download all files from a repository
hf download your-username/my-third-model

# Download to a specific local directory
hf download your-username/my-third-model --local-dir ./downloaded_model
```

### 5. Additional CLI Features

The CLI offers several other useful commands:

```bash
# Check authentication status
hf auth whoami

# List files in a repository
hf ls your-username/my-third-model

# Delete a file from a repository
hf delete your-username/my-third-model unwanted_file.txt
```

> [!TIP]
> The CLI is particularly useful in CI/CD pipelines, scripts, and when working with large files that benefit from resume capabilities. It also provides progress bars for large uploads and downloads!
